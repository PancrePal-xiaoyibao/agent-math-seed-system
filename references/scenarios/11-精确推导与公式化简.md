# 🎯 scenario · 精确推导与公式化简

> **问题信号**：
> - "帮我推导/化简这个公式，别给我近似值"
> - "这个导数/积分/极限我手算的结果，帮我核一遍"
> - "把这个函数泰勒展开到 n 阶，或者求一下级数"
> - "给数值代码生成解析梯度/雅可比，别用差分凑合"
> - "自定义梯度/损失对不对，怎么机器验证一下"
> - "这个递推数列的通项公式是什么"
>
> **典型任务**：
> 1. 推导核验：手推的公式在符号引擎里重算一遍，化简成最简形式再数值抽查
> 2. 为优化/仿真生成解析导数：符号求导 → 化简 → lambdify 编译成向量化数值函数
> 3. 近似与量阶分析：泰勒展开带余项，判断主导项与误差阶（如欧拉法误差）
>
> **主推组合**：**SymPy / CAS（主·符号演算引擎）+ 自动微分（辅·导数正确性验收）+ 泰勒展开（辅·近似与量阶）** —— CAS 负责"算得精确"，自动微分负责"代码化函数的导数可信"（符号核对+数值检验双保险），泰勒展开负责"近似时告诉你误差在哪一阶"；三者覆盖从纸面推导到代码落地的全链。
> **备选**：极限与洛必达 / 换元与分部积分 / 生成函数 / 递推求解 rsolve，详表见下。

---

## 🥇 主推工具详解

### A. 计算机代数系统 (SymPy / CAS)

**为什么适配**：凡是"要精确不要近似"的演算——解析求导、积分、解方程、极限、级数、化简——CAS 一次给全，而且不会像人手滑抄错一项。它的真正杠杆在"推导 → 代码"的桥：符号推出的闭式/雅可比，`lambdify` 一行编译成 numpy 向量化函数，公式错误和抄写错误同时消灭。核手算、给数值代码生成精确公式、教学演示，都是它。

**一句话 / 输入输出**：符号级代数引擎：解析求导/积分、方程求解、极限、级数展开、化简；符号表达式 → 化简/求导/积分后的表达式，可 `lambdify` 编译成 numpy 数值函数。

**陷阱**：
- 中间表达式指数膨胀（符号膨胀）：先 `sp.count_ops` 看规模，必要时 `sp.cse` 提公共子式，尽早化简退出符号域；
- "积不出" ≠ 积分不存在——多数积分本无初等闭式，sympy 会用 erf 等特殊函数表出，这是答案不是失败。

**代码入口**：`sympy.diff(f, x)` / `sympy.integrate(f, x)` / `sympy.solve(expr, x)` / `sympy.simplify(expr)` / `sympy.lambdify(x, expr, 'numpy')` → [recipes/12-符号计算与自动微分.md](../recipes/12-符号计算与自动微分.md)

**条目全文**：[domains/D-数值优化与ML与符号/D6-符号计算.md](../domains/D-数值优化与ML与符号/D6-符号计算.md)

### B. 自动微分 (Automatic Differentiation, forward/reverse)

**为什么适配**："代码写出的函数要求导"是本场景最高频的工程诉求：优化校准、仿真灵敏度、自定义层梯度验收。AD 不是数值差分也不是符号展开——是按链式法则精确传播，机器精度级。可信库内的小规模核对用 `sympy.diff`，自定义解析梯度上线前用中心差分做梯度检验（有限差分 tolerance 内一致才放行）；分支 if 与原地修改会悄悄制造错误计算图，是验出来的不是看出来的。

**一句话 / 输入输出**：把程序分解为基本算子后按链式法则精确传播导数：前向模式一次算一个输入方向，反向模式一次算全部参数梯度；程序 f: Rⁿ→Rᵐ → 机器精度级精确导数。

**陷阱**：
- 问题本身病态时梯度"精确而无用"——导数对了不代表结果可信，先看条件数（场景 07）；
- AD 只对"它看见的计算图"负责：分支 if、原地修改变量会让图失真；上线前必做有限差分梯度检验。

**代码入口**：可信库内 `sympy.diff(f, x)` 做小规模符号求导核对；数值校验用中心差分手写模板（见 recipes/12 梯度检验节）；工业级反向模式（JAX/PyTorch）属需安装依赖 → [recipes/12-符号计算与自动微分.md](../recipes/12-符号计算与自动微分.md)

**条目全文**：[domains/D-数值优化与ML与符号/D6-符号计算.md](../domains/D-数值优化与ML与符号/D6-符号计算.md)

### C. 泰勒展开 (Taylor Series)

**为什么适配**："精确推导"的另一面是"知道近似丢了多少"：光滑函数在展开点附近写成多项式+余项，主导项、误差阶、极值阶数全都能读出来——数值方法误差分析（欧拉法为什么是一阶）、未定式极限、近似计算都靠它。符号引擎展开时自带余项标记，比手写靠谱。

**一句话 / 输入输出**：f(x) 在展开点 a 附近写成多项式 + 余项（Peano/Lagrange）；f(x)、展开点、截断阶 n → 多项式近似 + 余项。

**陷阱**：
- 只在收敛半径内有效——对 |x|>1 用几何级数求和、或远离展开点截断，误差爆炸；先查收敛域再近似；
- 数值代入前先化简展开式，O(xⁿ) 记号不能直接进 numpy 计算。

**代码入口**：`sp.series(sp.exp(x), x, 0, 6)` —— 展开到指定阶并带余项；`.removeO()` 去余项后可 `lambdify` → [recipes/12-符号计算与自动微分.md](../recipes/12-符号计算与自动微分.md)

**条目全文**：[domains/B-分析与微分方程/B1-微积分.md](../domains/B-分析与微分方程/B1-微积分.md)

## 🥈 备选速览（何时升级为主推）

| 工具 | 一句话 | 何时用它当主推 |
|------|--------|---------------|
| 极限与洛必达法则 | 0/0、∞/∞ 未定式用导数比的极限代替原极限 | 出现"求 lim / ∞−∞ / 0·∞ / 比无穷小阶数"时：`sp.limit(sp.sin(x)/x, x, 0)`；幂指型先取对数化成 0/0——非未定式禁用洛必达 |
| 换元积分与分部积分 | 换元化简被积函数，分部转移导数，符号积分两大主力 | 要解析原函数/定积分闭式时：`sp.integrate(sp.x*sp.exp(x), x)` 自动选策略；积不出改 `scipy.integrate.quad` 数值（recipes/03），别死磕 |
| 生成函数 | 数列编码为幂级数 A(x)=Σaₙxⁿ，系数乘法即卷积 | 计数问题要闭式、解线性递推、背包方案数时：`sympy.series(expr, x, 0, n)` 展开取系数——详见场景 12 的计数主推 |
| 递推关系求解 rsolve | 线性递推 → 闭式通项 | 由递归结构求通项/核对分治复杂度时：`sympy.rsolve(f(n+2)-f(n+1)-f(n), f(n), {f(0):0, f(1):1})`；主定理三种情形的边界要人判，rsolve 管数列不管渐近证明 |

## ⚠️ 本场景翻车清单

- ❌ 推导完的符号公式直接进数值循环反复求值 → 每次调用都在做符号遍历，慢一个量级；`sp.simplify` 后 `sp.lambdify(..., "numpy")` 一次编译成向量化函数（忘写 `modules="numpy"` 只吃标量，也是高频翻车）。
- ❌ `integrate` 返回特殊函数/抛错就断言"积不出来，此路不通" → 多数积分本无初等闭式，erf/erfi 表出是正常答案；要数值就转 `scipy.integrate.quad`，别把"无闭式"当"无解"。
- ❌ 符号结果不做化简就数值代入 → 中间膨胀表达式既慢又放大舍入误差；先 `simplify`（大表达式 `cse` 提公共子式），lambdify 后立刻用小数组试跑一次抓未赋值 Symbol。
- ❌ 泰勒展开套在收敛半径外还报近似误差 → 先确认收敛域；远离展开点的截断误差爆炸，换展开点或改用全局近似。
- ❌ 数值差分把步长 h 取到 1e-10 以为更准 → 舍入误差 ~ε/h 与截断误差 ~h² 相抵，最优 h 约 ε^(1/3)，h 太小反而全是噪声；高精度换复步微分或 AD。
- ❌ 手推/自写梯度直接上线 → 拿中心差分做梯度检验（逐参数相对误差 < 容差）再放行；分支 if 与原地修改制造的错误计算图，只有检验能兜住。
