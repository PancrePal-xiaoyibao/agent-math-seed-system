# 🎯 scenario · 计数离散结构与空间

> **问题信号**：
> - "一共有多少种取法/方案/排列？" / "这个数怎么精确算出来"
> - "子集枚举 2^k 跑不动了" / "计数答案要取模，怎么不溢出"
> - "背包方案数 / 整数分拆 / 递推数列，能不能给个闭式"
> - "这些任务最多能同时安排几对 / 最少删几条边能把网络断开"
> - "给一堆点找外包边界 / 离群点 / 聚类外形"
> - "最近设施查询 / 站点空间插值 / 网格划分"
>
> **典型任务**：
> 1. 组合计数闭式：把计数递推编码成生成函数，幂级数展开取系数直接出答案
> 2. 可行性/输送建模：任务分配、最小割"最少断几条边"，建成网络流一次求准
> 3. 空间结构：点集外包边界（凸包）、最近设施划分（Voronoi）与邻域查询（KD 树）
>
> **主推组合**：**生成函数（主·计数闭式）+ 最大流最小割（辅·可行性建模）+ 凸包（辅·空间外形）** —— 计数问题在递推爆炸时生成函数把它变成代数操作；"最多配几对/最少断几条"这类可行性问题十有八九是网络流的建模壳；点集的空间问题先画凸包再谈其余——三者对应"计数 / 可行性 / 空间"三类信号，互不重叠。
> **备选**：排列组合与容斥 / Voronoi-Delaunay / 二分图匹配 / 递推与主定理，详表见下。

---

## 🥇 主推工具详解

### A. 生成函数 (Generating Function)

**为什么适配**：计数递推（背包方案数、整数分拆、数列通项）硬递推要么慢要么找不到规律——把数列编码成幂级数 A(x)=Σaₙxⁿ 后，"方案数合并"变成系数乘法（卷积），递推变代数操作：先解出 A(x) 的闭式，再展开取系数。它把"数数"升级成"算代数式"，是组合计数从暴力枚举跳到闭式的标准桥。

**一句话 / 输入输出**：把数列编码为幂级数，系数乘法即卷积，把计数递推变成代数操作；计数问题 → 生成函数 → 展开取系数即答案。

**陷阱**：
- 形式幂级数不关心收敛性——别用分析直觉（"这个级数发散啊"）先入为主；
- 从闭式提取系数时的部分分式分解是最易错环节，符号引擎展开取系数交叉核对。

**代码入口**：`sympy.series(expr, x, 0, n)` —— 幂级数展开取系数（闭式 → 系数） → [recipes/12-符号计算与自动微分.md](../recipes/12-符号计算与自动微分.md)

**条目全文**：[domains/A-代数与离散/A5-离散数学.md](../domains/A-代数与离散/A5-离散数学.md)

### B. 最大流与最小割 (Max-Flow & Min-Cut)

**为什么适配**："带容量约束最多输送多少"和"最少删多少边可断开 s 与 t"是同一道题（最大流 = 最小割），而且它是个万能建模壳：任务分配、项目选择、图像分割、二元约束都能装进去。自己写增广路容易错，网络图上直接 `nx.maximum_flow` 一次求准——建模对了答案就对了，这比启发式搜索可靠一个档次。

**一句话 / 输入输出**：沿残量网络反复增广求 s→t 最大流量，且最大流 = 最小割容量；容量网络 → 最大流值 / 最小割集。

**陷阱**：
- 残量网络必须含反向边，自写时漏建算法直接错误；
- 浮点容量有不停机风险，容量用整数；最小割解读前先确认源汇方向没接反。

**代码入口**：`nx.maximum_flow(G, s, t)` —— 返回 (流值, 流分布字典)；最小割 `nx.minimum_cut(G, s, t)`；只要流值用 `nx.maximum_flow_value(G, s, t)` → [recipes/02-图论与离散算法.md](../recipes/02-图论与离散算法.md)

**条目全文**：[domains/A-代数与离散/A5-离散数学.md](../domains/A-代数与离散/A5-离散数学.md)

### C. 凸包 (Convex Hull: Graham Scan / Andrew's Monotone Chain)

**为什么适配**："给一堆点找外形"是空间类问题的第一站：地理围栏、碰撞检测外扩、聚类外形勾勒、离群点检测、投资组合可达集边界——都是先求凸包拿到 O(n log n) 的精确边界，再谈细化。现成实现（Qhull）一行调用，自写 Graham/单调链也只是几十行；真正容易翻车的从来不是算法，是共线点与浮点判转向的细节。

**一句话 / 输入输出**：求包住点集的最小凸多边形，按排序 + 栈维护转向实现 O(n log n)；平面点集 → 逆时针顶点序列。

**陷阱**：
- 共线点与重复点的严格/非严格处理不一致（要顶点还是要边界点，先定语义）；
- 浮点叉积判转向要用相对容差，绝对容差在坐标量纲大时会把边界点误判进出。

**代码入口**：`scipy.spatial.ConvexHull(points)` —— 返回顶点索引 `hull.vertices`（Qhull 实现）；面积体积看 `hull.volume` / `hull.area` → [recipes/02-图论与离散算法.md](../recipes/02-图论与离散算法.md)

**条目全文**：[domains/D-数值优化与ML与符号/D7-计算几何.md](../domains/D-数值优化与ML与符号/D7-计算几何.md)

## 🥈 备选速览（何时升级为主推）

| 工具 | 一句话 | 何时用它当主推 |
|------|--------|---------------|
| 排列与组合 + 容斥原理 | P/C 公式四象限计数；容斥修正重复计数 | 直接计数且规模可控时别绕生成函数：`math.comb(n, k)` / `math.perm(n, k)` 精确整数，枚举方案用 `itertools.combinations`；数"至少满足一个"用容斥——但每个交集必须能精确算出，子集枚举 2ᵏ 在 k>20 就爆炸 |
| Voronoi 图与 Delaunay 三角剖分 | 按最近邻划分平面的对偶结构对 | "最近设施归属 / 自然邻域插值 / 网格生成"时：`scipy.spatial.Voronoi(points)`、`scipy.spatial.Delaunay(points)`，最近邻查询配 `scipy.spatial.cKDTree`；外推区域的无限大单元别当真实结构 |
| 二分图匹配 | 左右集合最大配对数（匈牙利 / Hopcroft–Karp） | "任务分配 / 师生配对 / 互不相邻选取"且左右结构天然二分时：`nx.bipartite.maximum_matching(H, top_nodes=...)`；先二染色确认真是二分图（含奇环则不是），König 定理只在二分图成立 |
| 递推关系与主定理 | 递推 → 闭式通项 / T(n)=aT(n/b)+f(n) 直接读复杂度 | 要通项公式用 `sympy.rsolve(f(n+2)-f(n+1)-f(n), f(n), {f(0):0, f(1):1})`；分析分治复杂度用主定理——f(n) 落在情形缝隙（如 n/log n）时主定理不适用，回手归纳证 |

## ⚠️ 本场景翻车清单

- ❌ 四象限公式选错（有序/无序 × 可重复/不可重复混用）→ 写公式前先答两个问题：顺序算不算数？元素能不能重复用？对照定 P/C/n^k/多重集组合，再动手算。
- ❌ 阶乘硬算 21! 溢出 int64 → Python 用 `math.comb/math.perm` 原生大整数；C++/Java 场景取模或取对数比大小；枚举前先估算 `comb(n,k)` 规模，别把 10⁹ 级方案真的一枚举。
- ❌ 容斥的子集枚举 2ᵏ 直接上（k=25 也要 3300 万次）→ k>20 换按位 DP / 统计技巧；且每个交集必须能精确算出，算不出的容斥是空中楼阁。
- ❌ 自写最大流漏建反向边 / 用浮点容量 → 前者直接错误、后者可能不停机；优先 `nx.maximum_flow`，容量一律整数化。
- ❌ 凸包判转向用绝对容差、共线点语义没定 → 用相对容差的叉积判转向；要"顶点"还是"含边界点"先声明（`ConvexHull` 的 qhull_options 对应选）。
- ❌ 把 Voronoi 无限单元 / Delaunay 超大外接三角形当真实结构解读 → 四点共圆退化需微扰；分析范围限制在数据凸包内，凸包外是外推区不是结构。
